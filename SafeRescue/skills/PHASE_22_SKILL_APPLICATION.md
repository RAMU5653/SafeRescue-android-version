# Phase 22 — Security Testing Skill Application

- **Security:** threat-model emergency, auth, evidence, network, BLE and LoRa boundaries.
- **Defensive coding:** reject unsafe URLs, malformed idempotency keys and retryable-auth loops.
- **Privacy:** never add secrets or sensitive data to test fixtures, logs or accessibility labels.
- **Reliability:** security failures must not disable the manual SOS path.
- **Testing:** combine static assertions with deterministic unit regression tests and document device/server tests still required.
- **Evidence:** report limitations honestly; no claim of penetration-test certification without a real environment.
